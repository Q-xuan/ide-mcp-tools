Run control, debugging & explicit DB writes for GoLand's MCP server

IDE MCP Tools adds run session control, debugging, and explicit database writes to GoLand's built-in MCP server. It uses your existing run configurations and database connections. Database writes follow the IDE's confirmation flow and respect read-only data sources.

IDE MCP Tools 为 GoLand 自带的 MCP 服务补充运行会话控制、调试和显式数据库写入。用户可以让已连接的客户端停止或重启指定测试进程、查看断点现场，并在 GoLand 的确认流程下对指定数据源执行写入。

Capabilities

Built around GoLand's native workflows

Reuses your existing run configurations, debug breakpoints, and IDE-managed database connections.

Run Session Control

List active Run and Debug sessions, gracefully stop specified test processes, or cleanly restart running services only after the old process exits.

list_run_sessions stop_run_session restart_run_configuration

Breakpoint & State Debugging

Start Debug from an existing run configuration, set line breakpoints, and inspect the call stack, local variables, and expressions when paused.

1-based lines 0-based frames xdebug_* compatible

Explicit Database Writes & Schema

Execute writes under GoLand's native confirmation flow and read-only restrictions. Refresh IDE-discovered schemas and sample metadata latency (SQLite runtime tested).

execute_database_write refresh_database_schema probe_database_metadata

Setup

Install & Connect

  1. 01
    Check your GoLand build number in Help → About.
  2. 02
    Open Settings → Plugins → ⚙ (Gear icon) → Install Plugin from Disk... and select ide-mcp-tools-0.1.4.zip. Restart the IDE if prompted.
  3. 03
    Enable the server under Settings → Tools → MCP Server and follow the on-screen instructions to connect your MCP client. Reconnect already-connected clients once to refresh the tool list. See the official GoLand MCP Server documentation.
  4. 04
    Open your target project (if multiple projects are open, specify the full project path to the client). Try asking your client to list active Run and Debug sessions for the project (calls list_run_sessions).

Workflows

What You Can Do

  • Restart a running service

    Find the sessionId with list_run_sessions, then call restart_run_configuration. The new process starts only after the old one exits and receives a new session ID.

  • Stop a specific test process

    Pass the session ID to stop_run_session. Uses graceful termination by default; forces termination only when force=true is explicitly passed and supported by the IDE.

  • Inspect where a program is paused

    Start Debug from an existing run configuration and set line breakpoints. Once paused, inspect the call stack, local variables, and evaluate expressions. GoLand 2026.3 native xdebug_* tools can also be used for new debug workflows.

  • Modify test data

    Identify the target data source and SQL, then execute via execute_database_write. GoLand's native confirmation flow and read-only restrictions remain enforced. Verify results afterward with native query tools.

  • Load database schema & probe metadata

    Use refresh_database_schema to load schemas discovered by the IDE (use native list_schema_objects to list objects). Use probe_database_metadata to sample metadata read latency (1 to 5 samples in a single call).

Common Notes

  • Session IDs for Run and Debug come from this plugin's session list. Always use the new ID after a restart. Sessions started before hot-loading the plugin that lack original configuration records can be listed and stopped, but restart requests will be rejected.
  • GoLand may need to compile first on the initial debug launch. If the start call times out, list sessions first to check whether the program actually started before retrying.
  • Stopping waits 10 seconds by default (configurable up to 60 seconds). A status of terminating means the process is still exiting.
  • Debug expression evaluation may invoke functions or mutate program state. Breakpoint source line numbers are 1-based; call stack frame indices are 0-based.
  • Database runtime testing for 0.1.4 covers SQLite.

安装并连接

  1. 01
    打开 设置 → 插件 → 齿轮 → 从磁盘安装插件，选择 ide-mcp-tools-0.1.4.zip。如果 IDE 提示重启，重启后继续。
  2. 02
    在 设置 → 工具 → MCP Server 启用服务，按页面提示连接你的 MCP 客户端。已经连接的客户端可以重新连接一次，刷新工具列表。参考 GoLand MCP 官方文档。
  3. 03
    打开目标项目。若同时开了多个项目，向客户端说明项目的完整目录。先试一句「列出这个项目正在运行的 Run 和 Debug 会话」，对应工具是 list_run_sessions。

可以怎么用

  • 重启正在运行的服务

    用 list_run_sessions 找到服务的 sessionId，再调用 restart_run_configuration。旧进程退出后才会启动新进程。新进程有新的 ID。

  • 停止指定测试进程

    用 stop_run_session 传入会话 ID。默认走正常退出。只有显式传 force=true 且 IDE 支持时才强制终止。

  • 看程序卡在哪里

    用已有运行配置启动 Debug，设置行断点。暂停后可以读取调用栈、局部变量和表达式结果。GoLand 2026.3 的原生 xdebug_* 工具也可用于新调试流程。

  • 改一条测试数据

    先确定临时数据源和 SQL，再用 execute_database_write 执行。GoLand 的原生确认和只读限制继续生效。执行后可用原生查询工具核对结果。

  • 加载数据库的表结构

    用 refresh_database_schema 加载 IDE 已发现的 schema。查询对象列表用原生 list_schema_objects。需要测元数据读取耗时时，可用 probe_database_metadata 在一次调用内采样 1 至 5 次。

几个常见情况

  • Run 和 Debug 的会话 ID 来自本插件的会话列表。重启后请用新的 ID。热加载前启动的会话若缺少原始配置记录，可列出和停止，重启会被拒绝。
  • 首次启动调试时 GoLand 可能需要先编译。启动调用超时后，先列出会话确认程序有没有启动，再决定是否重试。
  • 停止默认等待 10 秒，最长可设 60 秒。terminating 表示仍在退出。
  • 调试求值可能调用函数或改变程序状态。断点源码行号从 1 开始，调用帧序号从 0 开始。
  • 0.1.4 的数据库实测范围是 SQLite。
